Key Performance Risks

LCP: - Large hero section with video/animation (Cases page showreel, homepage animations) - Craft CMS with custom JS frontend likely has render-blocking scripts - LCP image likely not preloaded (<link rel="preload" as="image">) - No fetchpriority="high" on above-the-fold images

INP: - German legal requirement mandates a GDPR consent manager (Cookiebot, OneTrust, Borlabs, etc.) — these add significant main-thread blocking - GTM container loading ad pixels (LinkedIn, Meta, GA4) creates long tasks - scheduler.yield() or task-chunking likely absent

CLS: - Client logo grid (Vodafone, DKB, BBBank, etc.) — common CLS source when images load without explicit dimensions - Cookie banner injected at top of viewport shifts content down - Web fonts using font-display: swap can cause FOUT-based shifts

Quick Wins

  1. Add <link rel="preload" as="image" fetchpriority="high"> for hero image
  2. Add width + height to ALL <img> tags (especially client logos)
  3. Switch cookie consent banner to bottom overlay (reduces CLS)
  4. Load GTM and pixels asynchronously with async attribute
  5. Use font-display: optional for body fonts
  6. Add <link rel="preconnect"> for Google Fonts and GTM domains
